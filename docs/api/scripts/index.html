The scripts turn the downloaded data into the numbers, tables and figures of the paper, using the physics in fluxpy. Each one is run through pixi (for example pixi run numbers), or directly with pixi run python <script>. The text below is the docstring at the top of each script. scripts/ec_segment_placement.py¶

Run: pixi run placement · Source on GitHub

Segment-placement uncertainty of the EC sensible heat flux.

Where exactly a 5 km segment is cut out of a flight leg is arbitrary. To quantify what this choice does to the flux, a 5 km window is moved through every low-level leg in 0.05 km steps and the EC flux is computed at each position (same estimator as the segment fluxes: linear detrend, cospectrum integrated over 0.1-20 Hz). For each analysis segment, the placement uncertainty is the standard deviation of all window fluxes that overlap the segment, weighted by their fractional overlap (triangular weights).

Output: data/observations/ar/ec_segment_placement.nc Run: pixi run placement (about 2 minutes)

scripts/ec_window_length.py¶

Run: pixi run window-length · Source on GitHub

EC window-length experiment (manuscript Fig. 3).

Each low-level T-Bird leg is cut into consecutive sub-windows of length L (0.5 ... 50 km). For every L the mean EC flux of the sub-windows is compared with the EC flux of the stretch they cover (the remainder shorter than L is not part of any window). This ratio depends on where the window grid starts, because a window edge can cut through a strong flux event, so it is averaged over five grid positions (starting 0, L/5, ..., 4L/5 along the leg). The random error of the sub-window fluxes and the shares of sub-windows whose flux exceeds 1, 2 and 3 times its random error come from the grid that starts at the beginning of the leg. Same estimator as the segment fluxes (linear detrend, cospectrum integrated over 0.1-20 Hz).

Output: data/observations/ar/ec_leg_length_sensitivity/ec_sensitivity_summary.csv Run: pixi run window-length (about 10 minutes)

scripts/calc_bulk_and_ec_fluxes.py¶

Run: pixi run extract, pixi run precompute · Source on GitHub

Bulk fluxes for every forcing, the sensitivity sweep and the input perturbations.

Manuscript: Sect. 3.2 (bulk method), Sect. 4.1 (comparison, Table 3, Figs. 4-6), Sect. 4.2 (sensitivity, Table 4, Fig. 7), Table 2 (uncertainty budget), Appendix C.

Writes

data/model_output/sensitivity_figure_data.nc      every flux estimate on the 91 segments
data/model_output/sensitivity_summary_table.csv   skill of every configuration

Stages

1  load_obs             the 91 low-level segments over sea ice with the EC reference
2  along-track inputs   MODIS IST, ERA5 level 136 (T, wind, height), ERA5 skin temperature,
                        surface pressure and surface flux, CARRA surface flux, at each segment.
                        Cached in along_track_inputs.nc (pixi run extract) so that the bulk
                        computation runs without the gridded files.
3  sensitivity sweep    every configuration of Table C1, once with the ERA5-MODIS forcing
                        (sweep A) and once with the ERA5-only forcing (sweep B); the in-situ
                        estimate is part of every run
4  input perturbations  the reference configuration with T_s, T_air and U shifted by fixed
                        amounts, for the uncertainty budget and the input sensitivities
5  output

All physics comes from fluxpy (bulk, stability, sensitivity). The model-diagnosed fluxes of ERA5 and CARRA are positive downward in the products and are sign-flipped here, once, so that every H_* is positive upward.

scripts/manuscript_numbers.py¶

Run: pixi run numbers · Source on GitHub

Every number quoted in the manuscript text and in Table 3, printed from the pipeline output.

Single source of truth for the printed statistics. Run after any pipeline change and copy the numbers from here, never from an older PDF, a notebook or git history. pixi run check compares this output with expected_numbers.txt.

Precision, as printed in the paper: statistics (slopes and their intervals, correlations, biases, errors and uncertainties, sensitivities) with two decimals; flux values, temperatures, Ri_b and flight facts with one; counts and percentages as integers.

Blocks (in the order printed) and where they appear in the manuscript

EC reference ........................ Sect. 3.1, Appendix A2 (n, integrity check, random error, 1/2/3 sigma)
reference configuration ............. Table 3, Sect. 4.1 (slope, r, r2, within-leg r, bias, RMSE, CI)
amplitude-matched configuration ..... Sect. 4.2, Table C1 (alpha_T = 1e-2)
alpha_T sweep ....................... Sect. 4.2, Fig. 7, Table C1
satellite T_s benefit ............... Sect. 4.1, Discussion (heterogeneous vs homogeneous half)
alpha_T is a weak knob .............. Discussion
window-length experiment ............ Sect. 3.1, Fig. 3
uncertainty budget .................. Table 2
further numbers ..................... input sensitivities (Sect. 4.2), CARRA subset (Sect. 4.1), paired bootstrap
sample and flight facts ............. abstract, Sect. 2.1, 3.1, 4 (heights, airspeed, latitude, flux extremes)
percentages ......................... abstract, Sect. 4.1, Discussion, Conclusions (amplitude, variance, reduction)
Richardson number ................... Appendix B1 (range of Ri_b, effect of a bound)
zeta limit .......................... Appendix B1 (where the unstable-branch limit binds, effect of lifting it)

Framework (Sect. 4.1): amplitude skill is a regression slope and variability skill a correlation, because RMSE in this low-flux regime rewards estimates that shrink towards zero. The reference configuration uses the conventional alpha_T = 1e-1; the amplitude-matched alpha_T = 1e-2 is reported alongside.

Run: pixi run numbers

scripts/ec_quality.py¶

Run: pixi run ec-quality · Source on GitHub

Quality of the EC reference: every number of manuscript Appendix A.

Sections (numbered as printed)

1  Why ratio-type quality criteria are not used to discard segments: they respond to
   the size of the flux, not to the quality of the measurement (Appendix A3).
2  Robustness: slope and correlation of four estimates under eight alternative
   screenings (Table A1, written to tables_manuscript/table_qc_robustness.tex).
3  Random error: Finkelstein-Sims against surrogate data (which contain only the
   first term of the sum and are expected to be lower; Rannik et al., 2016) and
   against the segment-placement spread; sensitivity to the lag range; the factor
   missing from the shortcut form of the Lenschow et al. (1994) error (Appendix A2).
4  Physical consistency: the direction of the measured flux against the measured
   temperature difference, without any transfer coefficient (Appendix A4).
5  The pitch resonance of the towed T-Bird near 1 Hz: an upper bound of its effect
   on the fluxes and on the comparison (Appendix A4).

Run: pixi run ec-quality (about 1 minute; needs pixi run precompute)

scripts/robustness_checks.py¶

Run: pixi run robustness · Source on GitHub

Robustness of the comparison, printed from the pipeline output.

The checks test the statements of the manuscript against the choice of metric, errors in the reference, the dependence between neighbouring segments, the cloud cover of the satellite retrieval, the stability correction, the fitting of alpha_T and the measurement height. pixi run check compares this output with expected_numbers.txt like every other number.

Blocks (in the order printed) and what each one tests

1  more metrics ...................... the OLS slope is r times the ratio of standard deviations;
                                       intercept, sd ratio, mean absolute error, and what a
                                       zero-flux or constant forecast would score
2  errors in the reference ........... how much the random error of the EC flux flattens
                                       the regression slopes (regression dilution)
3  dependent segments ................ segments along a leg are not independent: confidence
                                       intervals with blocks of segments and legs as units,
                                       leave-one-day-out, the satellite gain under both
4  satellite surface temperature ..... how many segments have a genuine MODIS value, the
                                       comparison on those only, T_s of MODIS / ERA5 vs KT-19
5  stability ......................... sampled Ri_b, the stability factor f_h = C_h / C_h,n,
                                       and the per-segment spread of the eight schemes
6  alpha_T on withheld days .......... amplitude matching fitted on three days, tested on the fourth
7  measurement height ................ lower half vs upper half of the T-Bird heights

Run: pixi run robustness (needs pixi run precompute; about 10 s)

scripts/ec_band_sensitivity.py¶

Run: pixi run ec-bands · Source on GitHub

Sensitivity of the EC reference and of the comparison to the frequency band of the flux.

Manuscript Sect. 3.1 integrates the w-theta cospectrum over 0.1-20 Hz. The window-length experiment (Fig. 3) tests the consistency of that choice but not how much flux lies outside the band. Here every EC flux is recomputed from the 100 Hz data with other bands, and the comparison (slope b / correlation r of the three bulk estimates against the EC flux) is repeated with each of them. The first row reproduces the shipped EC fluxes.

A 5 km segment lasts about 81 s, so its lowest resolved frequency is about 0.012 Hz; bands that start below 0.05 Hz rest on one or two cycles and are not used.

Run: pixi run ec-bands (about 30 s)

scripts/check_expected_numbers.py¶

Run: pixi run check · Source on GitHub

Compare the numbers printed by the number scripts with expected_numbers.txt.

expected_numbers.txt is the committed output of manuscript_numbers.py (text and Table 3), ec_quality.py (Appendix A), robustness_checks.py and ec_band_sensitivity.py (robustness of the comparison) for this version of the repository. Numbers are compared with a tolerance of 0.02 (two units in the last digit of a two-decimal statistic) so that harmless floating-point differences between operating systems do not raise a false alarm.

docs/build_api.py¶

Run: pixi run api · Source on GitHub

Write the API reference (docs/api/) and the figure pages (docs/figures/) of the website.

MyST, the engine of the website, has no autodoc. This script does what Sphinx’s autodoc and autosummary do for a Sphinx site:

  • one page per fluxpy module, in the order of the module map in fluxpy/__init__.py (paper order): the module docstring, a summary table, every public constant (value and the #: comment of its definition), class (fields with type, default and meaning) and function (signature, parameter table with types and defaults, docstring), each with a link to the source on GitHub and the source itself;

  • one page on every script (scripts/, figures_manuscript/, the book, paper and website builders): its docstring and the pixi task that runs it;

  • an index page;

  • one page per manuscript figure (docs/figures/): the figure, its caption from the manuscript (docs/figures/captions.json, written here from the reading copy of the manuscript when it lies next to this repository), the docstring of its script, the fluxpy objects it uses, and the script itself.

Docstrings are plain text with a little reStructuredText (code``, :func:`` roles, underlined headings, numpydoc Parameters sections, simple tables, :: literal blocks) and $...$ math; they are translated to MyST markdown here, and every name that is documented becomes a link.

The pages are committed like the executed book chapters, so the website build needs neither the data nor the analysis environment. tests/test_api_docs.py fails when a docstring or signature changed and the pages were not rebuilt.

Run: pixi run api

Other scripts¶

scripts/data_manifest.py¶

Run: pixi run data-manifest · Source on GitHub

Checksum manifest of the data files (data/manifest.tsv), and where each file is archived.

The paper’s numbers were computed from exactly these bytes. The manifest records, for every data file, its size, its SHA-256 checksum and the archive it is published in, so that a file downloaded from PANGAEA or Zenodo can be checked against the file the numbers came from (DATA_PUBLICATION.md describes the publication of the data).

Archive column:

pangaea:published   already published on PANGAEA (source: its DOI)
pangaea:new         derived from the measurements; to be published on PANGAEA by the authors
zenodo:data         subsets of third-party gridded products; to be published on Zenodo
regenerated         written by the pipeline (pixi run precompute); not archived
unused              not read by any script; not archived

Run:

pixi run data-manifest            check every listed file (size and checksum)
pixi run data-manifest --write    recompute size and checksum; new files get the archive
                                  of the first matching rule below, existing rows keep theirs

scripts/fetch_pangaea.py¶

Run: pixi run fetch-pangaea · Source on GitHub

Download the published PANGAEA files the analysis starts from, into data/pangaea//.

The measurements are published in the bundle “Observations from the BACSAM II aircraft campaign with Polar 6” (Köhler et al., 2026, doi:10.1594/PANGAEA.995979). This script fetches the netCDF files of three of its datasets, one file per research flight, about 1.5 GB:

995975  T-Bird, 100 Hz
995974  Polar 6 nose boom, 100 Hz
995980  KT-19, 50 Hz

It also fetches the 13 Polar 6 master tracks of the campaign (Jurányi et al., 2024, doi:10.1594/PANGAEA.971763; one dataset per flight, as PANGAEA text export) into data/observations/raw/polar6/mastertracks/, which Fig. 1 reads.

Every file is checked against the size and SHA-256 checksum of the file the paper’s numbers were computed from; a file that is already present and correct is not downloaded again. PANGAEA serves some files from tape and then answers HTTP 503 for a while; the script waits and retries. scripts/prepare_inputs.py (pixi run inputs) then cuts the files to the low-level legs.

Run: pixi run fetch-pangaea

scripts/prepare_inputs.py¶

Run: pixi run inputs · Source on GitHub

Published PANGAEA data -> the input files of the analysis, cut to the low-level legs.

The measurements are published in the bundle “Observations from the BACSAM II aircraft campaign with Polar 6” (Köhler et al., 2026, doi:10.1594/PANGAEA.995979). The netCDF files of the datasets below are expected in data/pangaea// (one file per research flight; pixi run fetch-pangaea downloads them):
